# ACP Components

This Storybook documents the public React components for Agent Client Protocol hosts.
It runs as a private workspace and imports components through `@acp-components/react`,
the same entry point used by consumers.

Use the toolbar to inspect every story in the dark or light theme and in English
or Chinese. Stories that depend on ACP sessions, platform capabilities, files, or
permissions run against deterministic in-memory fixtures and never connect to a
real agent.

## Documentation structure

- **Foundations** covers design tokens and theme behavior.
- **Layer 1 - Props & Context** contains components driven by props, local state,
  or lightweight ambient contexts such as i18n, platform, settings, and hotkeys.
- **Layer 2 - Store Driven** contains components and providers that read or write
  ACP Zustand stores directly, through package hooks, or through store-owned
  children and synchronization sidecars.
- **Layer 3 - Pages & Patterns** contains complete pages, application shells, and
  cross-component compositions. This classification takes precedence when a page
  also consumes store-driven children.

The layer labels describe runtime ownership, not visual size. Foundations remain
outside the component layers because they document tokens rather than a public
React component.

## Runtime providers

The preview recreates the package's provider contract without starting a transport:

```text
PlatformContext
  -> HotkeysProvider
    -> I18nProvider
      -> SettingsContext
        -> AcpContext
          -> Story
```

State-backed stories reset the core Zustand stores before seeding their own data,
so switching between stories cannot leak sessions, permissions, files, or skills.
